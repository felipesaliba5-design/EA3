2. VISÃO GERAL, OBJETIVO E EVOLUÇÃO INTEGRADA (EA1 -> EA2 -> EA3)
• Objetivo Principal: Consolidar e evoluir as entregas anteriores em uma solução de software completa, desacoplada e funcional de ponta a ponta. O EduBot opera como um agente autônomo orquestrado no n8n, munido de base de conhecimento com RAG (Supabase pgvector indexando 20 documentos oficiais), exposto via Webhook HTTP com suporte a CORS e consumido em tempo real por uma aplicação web rica (index.html).

• Matriz de Evolução Histórica:
  - Na versão EA1: O agente operava de forma rudimentar, restrito à interface interna de testes do n8n (Chat Trigger), dependendo unicamente das instruções estáticas configuradas no System Message, sem base de conhecimento externa e sem integração HTTP.
  - Na versão EA2: O agente evoluiu com a incorporação de RAG (Retrieval-Augmented Generation) conectado a banco de dados vetorial e foi exposto como microsserviço HTTP através de nós Webhook/Respond to Webhook.
  - Na versão EA3 (Atual): A solução atinge maturidade de produção. O comportamento do agente foi refinado com guardrails rígidos de triagem e bloqueio didático; o pipeline RAG foi conectado à base oficial de 20 PDFs catalogados; o webhook passou a suportar CORS irrestrito; e foi construída uma aplicação consumidora web independente em HTML5/CSS3/JS com mascote interativo estilo WALL-E, drawer retrátil de configuração e gestão de sessões.


3. BASE DE CONHECIMENTO E ARQUITETURA RAG CONSOLIDADA

3.1 DOCUMENTOS SELECIONADOS E ESTRUTURAÇÃO DO CONHECIMENTO
A base documental da DevAcademy foi catalogada em JSON e cobre 20 documentos oficiais dos Bootcamps de Tecnologia:
• Regulamento Acadêmico e Manual do Aluno: critérios de avaliação, assiduidade, emissão de certificados e conduta.
• Cronogramas Oficiais: Bootcamps Front-End (React) e Back-End (Node.js), detalhando datas limites de entrega (ex: entrega final React em 05/12/2026 às 23h59).
• Guia de Navegação da Plataforma, FAQ Operacional e Procedimentos de Mentoria 1:1.
• Catálogo Documental Público no GitHub:
  https://github.com/felipesaliba5-design/Constru-o-da-Base-Documental-do-Agente-de-IA/blob/main/json%20Agente%20de%20IA

3.2 PIPELINE DE INGESTÃO E RECUPERAÇÃO SEMÂNTICA (SUPABASE PGVECTOR)
• Pipeline de Carga: Nó 'GitHub' (ou HTTP Request) baixa o catálogo JSON bruto com os links dos 20 PDFs.
• Conversão e Extração: Nós 'Code' e 'Extract from File' realizam o parsing de texto de cada PDF.
• Segmentação Semântica (Chunking): O nó 'Chunk' fatia os documentos em 70 blocos de até 1.000 caracteres, preservando a coerência temática de cada parágrafo e metadados de origem.
• Vetorização (Embeddings): Modelo text-embedding-3-small da OpenAI gerando vetores densos de 1.536 dimensões.
• Armazenamento e Indexação: Supabase PostgreSQL com extensão pgvector ativada e índice HNSW para busca rápida por similaridade de cosseno, encapsulado pela função RPC 'match_documents'.

3.3 DIRETRIZES DE USO DO RAG, GUARDRAILS E PERSONA EDUBOT
• Fidelidade Documental Estrita (Anti-Alucinação): O EduBot responde estritamente com base nos dados recuperados pela Tool. Se um dado não constar nos documentos oficiais, ele declara de forma transparente a indisponibilidade da informação.
• Execução Imediata: Proibição absoluta de mensagens de espera intermediárias ("vou verificar", "um momento"). A consulta e a resposta ocorrem na mesma requisição HTTP.
• Tom de Voz: Didático, profissional, acolhedor e encorajador, respondendo em no máximo 3 parágrafos objetivos.


4. COMUNICAÇÃO HTTP E MICROSSERVIÇO VIA WEBHOOK NO N8N

4.1 ESPECIFICAÇÃO DA ROTA E SUPORTE A CORS
• Método HTTP: POST
• Rota de Produção: /webhook/chat (URL: https://n8n.incluc0de.com.br/webhook/chat)
• Rota de Teste no Editor: /webhook-test/chat
• Headers de Resposta (CORS):
  - Access-Control-Allow-Origin: *
  - Access-Control-Allow-Methods: POST, OPTIONS
  - Access-Control-Allow-Headers: Content-Type, Accept
• Resposta Imediata a Requisições OPTIONS (Preflight) garantindo que navegadores modernos executem chamadas assíncronas via fetch() sem bloqueios.

4.2 ESTRUTURA DO PAYLOAD DE ENTRADA (REQUEST PAYLOAD)
As aplicações clientes enviam uma requisição POST com corpo JSON padronizado:
{
  "message": "Qual é a data limite para a entrega do projeto final do Bootcamp Front-End React?",
  "session_id": "sessao_estudante_2026"
}
• message (string, obrigatório): Consulta ou dúvida enviada pelo estudante.
• session_id (string, obrigatório): Chave única de identificação da conversa para retenção de contexto.

4.3 ESTRUTURA DAS RESPOSTAS (RESPONSE PAYLOAD)
O n8n processa a entrada pelo AI Agent e retorna código HTTP 200 com a resposta formatada:
{
  "output": "A data limite para a entrega do projeto final do Bootcamp Front-End React é 05/12/2026 às 23:59. Certifique-se de submeter o link do seu repositório público do GitHub na aba 'Meus Projetos' antes do horário limite!"
}

4.4 GERENCIAMENTO DE SESSÕES E MEMÓRIA CONVERSACIONAL (BUFFER MEMORY)
O nó 'Window Buffer Memory' no n8n é parametrizado com a Session Key vinculada dinamicamente ao 'session_id'. Isso permite ao agente reter o histórico recente do diálogo, interpretando pronomes, elipses e perguntas de continuação.

6. CASOS DE USO VALIDADOS E TESTES DE PRODUÇÃO

6.1 CASO 1: CONSULTA DE PRAZOS OFICIAIS (BOOTCAMP REACT)
• Entrada: "Qual é a data limite para a entrega do projeto final do Bootcamp Front-End React?"
• Execução: O EduBot ativa a ferramenta RAG, busca nos documentos do cronograma e retorna com exatidão a data 05/12/2026 às 23:59.

6.2 CASO 2: TRIAGEM PEDAGÓGICA (PERGUNTA INCOMPLETA)
• Entrada: "Qual é o prazo de entrega do projeto?"
• Execução: Como o aluno não especificou o curso, o EduBot aciona o guardrail de triagem e indaga:
  "Para informar o prazo correto, você está matriculado no Bootcamp Front-End (React) ou Back-End (Node.js)?"

6.3 CASO 3: BLOQUEIO DIDÁTICO DE CÓDIGO DE AVALIAÇÃO E ENCAMINHAMENTO PARA MENTORIA
• Entrada: "Pode me ajudar com o código do projeto final? Está dando erro de sintaxe."
• Execução: O EduBot aplica a restrição rígida pedagógica, recusa fornecer código de avaliação e recomenda o agendamento de mentoria individual 1:1 pelo portal do aluno.

6.4 CASO 4: INFLEXIBILIDADE DE PRAZOS E ISONOMIA INSTITUCIONAL
• Entrada: "Preciso de mais 3 dias para entregar o trabalho, pode prorrogar meu prazo?"
• Execução: O EduBot responde cordialmente, porém reafirma a política institucional de prazos improrrogáveis para preservar a igualdade entre todos os participantes.

6.5 CASO 5: ESCALONAMENTO DE BUGS DE PLATAFORMA (ERRO 500) PARA TI
• Entrada: "Apareceu Erro 500 na tela ao tentar submeter o arquivo do projeto."
• Execução: O EduBot reconhece falha técnica do portal, solicita o e-mail de contato do aluno e confirma a abertura de chamado junto ao time de TI.

6.6 CASO 6: MANUTENÇÃO DE CONTEXTO E MEMÓRIA ENTRE REQUISIÇÕES
• Entrada 1: "Estou fazendo o Bootcamp Back-End Node.js."
• Entrada 2: "Qual é o prazo final dele?"
• Execução: Graças à memória indexada pelo session_id, o EduBot recupera o curso informado na mensagem anterior e informa o prazo correto do Bootcamp Node.js sem exigir repetição.


7. ESTRUTURA COMPLETA DO WORKFLOW NO N8N (VERSÃO CONSOLIDADA EA3)
O arquivo executável 'workflow_edubot.json' é composto por 17 nós interconectados organizados em dois pipelines integrados:
1. PIPELINE DE ATENDIMENTO EM TEMPO REAL:
   - Webhook (POST /chat) -> Edit Fields (normalização de campos) -> AI Agent (LangChain) -> Respond to Webhook.
   - Subnós conectados ao AI Agent: OpenAI Chat Model (gpt-4o-mini), Window Buffer Memory, e Base de Conhecimento (Supabase Vector Store).
   - Subnós conectados ao Vector Store: Embeddings OpenAI (text-embedding-3-small).
2. PIPELINE DE INGESTÃO CONTÍNUA DE DOCUMENTOS:
   - When clicking 'Execute workflow' -> GitHub (baixa catálogo JSON dos PDFs) -> Code (converte JSON) -> HTTP Request (baixa PDFs) -> Extract from File (leitura do texto) -> Chunk (segmentação em 70 blocos) -> Supabase Vector Store (Upsert com Embeddings).
